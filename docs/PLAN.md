# خطة SSAS — النسخة 2 (حضور أول الحصة بنموذج لكل فصل)

## Context
بعد كلام الأستاذ ومراجعة القرارات، المشروع اتبسّط جداً:
- **مفيش مراقبة للطلاب.** الكاميرا بتفتح **في أول كل حصة بس**، بتسجّل الحضور **مرة واحدة**، وبعدين بتقفل وتبعت النتيجة كنص.
- **كل شاشة بتتعرف على طلاب فصلها بنفسها**، بنموذج متدرب على بيانات الفصل ده بس.
- **التصوير والتدريب بيتعملوا على اللابتوب.** وبعدها بننقل النموذج والبيانات والتطبيق بفلاشة لكل شاشة.
- **السيرفر بيستقبل نص بس** (مين حاضر ومين غايب). ومعلم الحصة بيصحح من صفحة ويب على موبايله.
- **المطلوب دلوقتي:** شكل صفحة المعلم بس (UI)، من غير تسجيل دخول حقيقي ومن غير ما تكون شغالة.
- المشروع ده هيتستخدم بعدين في **مدارس تانية واستخدامات تانية**، فالكود لازم يكون مرن وسهل التعديل.

الخطة القديمة (المراقبة المستمرة، والـ tracking، وأذونات الخروج بالكاميرا، وبصمة الجسم، وتشغيل الـ ML على السيرفر) **اتلغت**، والخطة دي بتحل محلها.

## 0. القرارات
| البند | القرار |
|---|---|
| الشاشة | Hikvision، غالباً **DS-D5C65RB/B** (نسخة من غير Google، لأن GSF ID فاضي في صفحة About). Android 13، رام 8 جيجا، معالج غالباً RK3588، وكاميرا 4K |
| الكاميرا | بتفتح **بعد الجرس بـ 3 دقايق**، وتفضل **5 دقايق بحد أقصى**، وتقفل بدري أول ما كل الطلاب يتعرف عليهم. الأدمن يقدر يغيّر الأوقات دي. **ممنوع حد يخرج والكاميرا بتسجل** |
| التعرف | **على الشاشة نفسها**، بنموذج الفصل اللي اتعمل على اللابتوب. ومفيش أي صور بتخرج من الشاشة |
| التدريب | **على اللابتوب** (بكارت الشاشة). بياخد دقايق، وبيتعاد أكتر من مرة لحد ما النتيجة تبقى صح |
| النقل للشاشة | **بالفلاشة**: فولدر منظّم فيه التطبيق + النماذج + فولدر لكل فصل |
| المتأخر | يتسجل **غائب**، والمعلم يصححه من صفحته |
| أذونات الخروج | مفيش بالكاميرا. **المعلم بيعلّم يدوي** (حمام، هارب، متأخر وبرا). ومعاها **كشف تلقائي للهروب بين الحصص**: طالب كان حاضر في حصة وغايب في اللي بعدها |
| المراجعة | **معلم الحصة** من موبايله، ويقدر يعدّل **حصته الحالية بس** |
| الأدوار | المطوّر = كل الصلاحيات · المشرف = عرض فقط · المعلم = فصله في حصته بس |
| السيرفر | كمبيوتر ضعيف، **ومفيش عليه أي ML**. Ubuntu Server 24.04 LTS |
| الشبكات | كل جهاز على شبكة مختلفة: الشاشات (شبكتها أو الهوت سبوت بتاعها)، ولابتوب الأدمن، والمعلمين، والسيرفر. وشرطك: **الموقع ما يكونش Public** (القسم 6) |
| اللغة | English، مع دعم الأسماء العربي |

## 1. دور كل جهاز
```
 ┌─ لابتوب الأدمن (Windows + GPU) ─ "SSAS Studio" ───────────────┐
 │ تصوير الطلاب (Face-ID ring) → تنظيم البيانات لكل فصل →         │
 │ تدريب نموذج الفصل (دقائق، مرات عديدة، تقرير دقة) → تصدير فلاشة │
 └──────────────────────────┬─────────────────────────────────────┘
                            │ فلاشة USB (مرة لكل فصل/تحديث)
                            ▼
 ┌─ الشاشة (Android) ─ "SSAS Board" ─────────────────────────────┐
 │ تعرف فصلها من الجدول → أول الحصة: كاميرا 5 دقائق بحد أقصى →    │
 │ تعرّف على الطلاب محلياً → تقفل الكاميرا → ترسل JSON نصي          │
 └──────────────────────────┬─────────────────────────────────────┘
                            │ HTTPS (نص فقط)
                            ▼
 ┌─ السيرفر (PC ضعيف، Ubuntu) ───────────────────────────────────┐
 │ يستقبل النتائج · الجدول · حسابات المعلمين · التقارير · الرسوم   │
 │ · كشف "غاب بعد ما كان حاضر" · يخدم صفحة المعلم ولوحة الأدمن     │
 └──────────────┬───────────────────────────┬────────────────────┘
                ▼                           ▼
     موبايل المعلم (صفحة ويب)        لوحة الأدمن/المشرف (ويب)
```
| الجهاز | شغله | اللي **مش** شغله |
|---|---|---|
| **اللابتوب** | التصوير، والتدريب، والتقييم، والتصدير للفلاشة، وفتح لوحة الأدمن | ما بيسجلش الحضور اليومي |
| **الشاشة** | تصوّر في أول الحصة، وتتعرف على الطلاب، وتبعت نص | ما بتسجلش فيديو، وما بتبعتش صور، وما بتشتغلش طول الحصة |
| **السيرفر** | البيانات، والجدول، والصفحات، والتقارير | مفيش عليه ML ولا صور |
| **موبايل المعلم** | يشوف الحصة الحالية ويصحح | مش بيشوف غير فصله في حصته |

**ليه ده خفيف على الشاشة:**
- الكاميرا ما بتشتغلش غير دقايق قليلة في أول الحصة.
- المعالجة حوالي ثواني في الحصة كلها، بأولوية منخفضة.
- طول باقي الحصة التطبيق نايم وما بيستهلكش حاجة.

## 2. اللابتوب — SSAS Studio (Python، Windows)
- **التقنية:** **Python + PySide6 (Qt)** للواجهة، و**OpenCV** للكاميرا، و**ONNX Runtime (GPU/CPU)** لاستخراج البصمات، و**PyTorch (CUDA)** للتدريب. وبيتحزم لـ Windows بـ PyInstaller.
- **الخطوات:**
  1. **بيانات المدرسة:** الصفوف ← المسار ← الشعبة ← الطلاب. يدوي أو باستيراد Excel، **ومن غير بيانات وهمية**.
  2. **التصوير:**
     - كاميرا اللابتوب أو كاميرا USB خارجية.
     - **دايرة زي Face ID** باستخدام MediaPipe Face Landmarker. أجزاء الدايرة بتتملي مع اتجاهات الراس، **والاتجاهات بترتيب عشوائي**، ومعاها رمش العين.
     - **شخص واحد بس في الصورة** (لو ظهر حد تاني، التصوير يقف).
     - فحص الجودة: الحجم، والوضوح، والإضاءة.
     - **فحص التكرار** على المدرسة كلها، علشان محدش يتسجل مكان صاحبه.
     - حوالي 60–100 صورة لكل طالب.
  3. **التدريب لكل فصل** (دقايق على كارت الشاشة):
     - **العمود الفقري (Backbone):** نموذج تعرف على الوجوه متدرب مسبقاً (**AdaFace IR-50** بصيغة ONNX)، ومش بيتغير. ده نفس الملف اللي بيشتغل على الشاشة، فالنتايج متطابقة.
     - **Augmentation مكثّف** علشان صور اللابتوب تشبه صورة الكاميرا من آخر الفصل: تصغير الوش لحد 20–48 بكسل، وتغبيش، وضغط JPEG، وإضاءة وألوان مختلفة، وتغطية جزء من الوش، ودوران بسيط.
     - **رأس تصنيف (Head) خاص بالفصل:** مصنّف cosine بـ margin loss.
     - **التدريب بيتعاد كذا مرة:**
       - عدد كبير من الـ epochs.
       - **K-fold cross-validation** (مثلاً 5 مرات).
       - أكتر من seed، ونختار الأفضل أو نعمل ensemble.
     - **كشف "مش من الفصل":** طلاب الفصول التانية بيتستخدموا **كأمثلة سلبية**. ومنهم بيتظبط حد الثقة، علشان الشاشة ترفض أي حد غريب: معلم، أو طالب من فصل تاني، أو صورة.
     - **تقرير جودة:**
       - دقة التعرف.
       - نسبة الخلط مع الغرباء.
       - أضعف الطلاب في الصور، مع اقتراح إعادة تصويرهم.
       - **ما نسمحش بالتصدير** إلا لو التقرير عدّى الحد المطلوب.
  4. **التصدير للفلاشة:** فولدر منظّم ومتشفّر (القسم 3.1).
  5. **لوحة الأدمن:** تاب جوه Studio بيفتح لوحة الويب من السيرفر، بالدخول بإيميل + باسورد + TOTP.
- **مكان البيانات على اللابتوب:** فولدر `SSAS-Data/` متشفّر (BitLocker أو تشفير التطبيق)، ومقسّم كده: `classes/<class-id>/students/<student-id>/photos/`.

## 3. الشاشة — SSAS Board (Kotlin، Android 13)
### 3.1 محتوى الفلاشة
```
SSAS-USB/
├── app/ssas-board.apk
├── models/            # مشتركة: person/pose (RTMO-s), face detect (YuNet), face embed (AdaFace) — ONNX
├── classes/
│   └── 9-ADV-4/
│       ├── manifest.json      # الفصل، الطلاب (ID + الاسم)، نسخة النموذج، الحدود، checksums
│       └── class-model.enc    # رأس التصنيف + البصمات المرجعية (مشفّر، بدون صور)
└── board/<board-id>.json      # رابط السيرفر + مفتاح الشاشة + الغرفة (يولّده الأدمن)
```
- **صور الطلاب ما بتتنقلش للشاشة خالص**. اللي بيتنقل البصمات الرقمية ورأس التصنيف بس.
- **شاشة المعمل:** بيتحط عليها فولدرات **كل الفصول اللي بتيجي المعمل**، والشاشة بتختار الفولدر الصح حسب الجدول.
- التطبيق بيستورد الفلاشة من شاشة "Import" بتاعته، ويتأكد من الـ checksums، وينقل الملفات لتخزينه الخاص.

### 3.2 التشغيل والجدول
- **Auto-Launch** من إعدادات Hikvision بيفتح شاشة "Arm" صغيرة مع تشغيل الجهاز. الشاشة دي بتشغّل Foreground Service من نوع `camera` (وده اللي بيحافظ على صلاحية الكاميرا طول اليوم)، وبعدين تقفل.
- لو الخدمة وقفت في نص اليوم:
  - تتعلّم `NO_DATA_UNARMED`، **ومش بتتحسب غياب**.
  - الأدمن بيوصله تنبيه.
  - الخدمة بترجع بضغطة على **Widget "Re-arm"** على الشاشة، أو مع ريستارت الجهاز بالليل.
- **الشاشة بتعرف فصلها من الجدول:** بتسحب الجدول من السيرفر وبتحفظه عندها. ولو النت فصل، بتشتغل بالنسخة المحفوظة.
- **الوقت** بيمشي على وقت السيرفر، مش ساعة الشاشة.

### 3.3 أول الحصة (نافذة التسجيل)
1. **الوقت:** بداية الحصة + 3 دقايق + تأخير صغير بيختلف من شاشة للتانية.
2. **Camera2** (مش CameraX)، بأكبر مقاس JPEG متاح، وبعد تسخين 2–3 ثواني للكاميرا.
3. **لقطات** عند +0، +10، +25، +45، +75 ثانية، ولحد 5 دقايق بحد أقصى. **وبتقف بدري** أول ما كل طلاب الفصل يتعرف عليهم.
4. **المعالجة على الشاشة:**
   - **RTMO** على الصورة بعد تصغيرها: بيعدّ الأجسام وبيرسم الـ stick-man.
   - **YuNet** على قصاصات الرؤوس من الصورة الكاملة.
   - **AdaFace** + رأس الفصل ← اسم الطالب أو "مش من الفصل".
   - **ربط الوش بالجسم:** أي وش من غير جسم (صورة أو موبايل) بيترفض.
5. **المحرّك:** **ONNX Runtime Android** على الـ CPU. نفس ملفات اللابتوب، بخيطين وبأولوية Background. وتحسين الأداء بالـ NPU (RKNN) ممكن بعدين لو احتجناه.
6. **القرار على الشاشة، لكل طالب:**
   - **حاضر:** اتعرف عليه في لقطتين، أو في لقطة واحدة بثقة عالية.
   - **غائب:** ما اتعرفش عليه **و**مفيش أي جسم مجهول في الفصل **و**اللقطات كانت سليمة.
   - **للمراجعة:** فيه أجسام مجهولة، أو الوش ما ظهرش كويس.
   - **لا توجد بيانات:** الكاميرا مش متاحة (معلم شغال على OPS، أو تطبيق تاني ماسك الكاميرا، أو الصورة سودا أو متغطية).
7. **إرسال JSON**، وفيه:
   - `board_id` و`class_id` والحصة والتاريخ.
   - `present[]` و`absent[]` و`needs_review[]` و`unknown_count`.
   - حالة الكاميرا، ونسخة النموذج، والتوقيت.
   
   الإرسال **نص بس**. ولو مفيش نت، بيتخزن ويتبعت بعدين.
8. **الكاميرا بتقفل.** وأي صورة بتتمسح من الذاكرة فوراً.

### 3.4 الواجهة والخفة
- لما التطبيق يتفتح: **الكاميرا + مربع حوالين كل راس + stick-man** (بلون واحد ومن غير أسماء). ومعاها شاشة "Import" للفلاشة.
- **مفيش أي إعدادات للمعلم**، وصوت خفيف بس.
- **Heartbeat كل 5 دقايق**، وفيه: الشاشة متجهزة ولا لأ، وحالة الكاميرا، والإصدار، وآخر خطأ. ده بيظهر في لوحة الأدمن.
- **قبل التعميم نظبط في إعدادات الشاشة:**
  - **نقفل Auto-framing / Speaker tracking.**
  - **نقفل الهوت سبوت أو نحطه بباسورد قوي** (أي جهاز بيدخل عليه بياخد نفس الـ IP بتاع الشاشة).
  - نشغّل الشاشة بالكابل لو ينفع.

## 4. السيرفر (خفيف، ومفيش عليه ML)
- **Ubuntu Server 24.04 LTS** + Docker Compose بـ 3 خدمات: `caddy` و`api` (FastAPI + APScheduler) و`postgres:17`. وباب واحد بس مفتوح هو 443.
- **وظايفه:**
  - استقبال نتايج الشاشات (بمفتاح خاص لكل شاشة، والشاشة متربطة بغرفتها).
  - الجدول وأنواع الحصص (فسحة، وطابور، ورياضة، كلها مش بتتحسب).
  - حسابات المعلمين.
  - تصحيحات المعلم، وكل تصحيح متسجل في Audit log.
  - **"غاب بعد ما كان حاضر"** (هروب بين الحصص) + تنبيه.
  - التقارير لكل حصة وكل يوم، والرسوم البيانية، والتصدير لـ Excel.
  - لوحة الأدمن (إيميل + باسورد + TOTP)، والمشرف عرض فقط.
- **نسخ احتياطي من أول يوم:** `pg_dump` + restic على هارد USB، ومعاها NTP.

## 5. صفحة المعلم (Web — موبايل أولاً)
- **الدخول:** بالإيميل والباسورد، والصفحة **بتفتكر المعلم**.
- الأدمن بيدخّل جدول المعلمين. فلما المعلم يفتح الصفحة، بيتفتح له **Dashboard الفصل اللي هو فيه دلوقتي**، ويقدر يعدّل **عليه بس**.
- **قائمة الطلاب:** كل طالب جنبه **دايرة ملوّنة** + اسمه + كلمة الحالة (علشان اللون مش هو الدليل الوحيد). المعلم يضغط على الطالب ويختار حالته.

| الحالة | اللون |
|---|---|
| Present (حاضر) | 🟢 أخضر |
| Escaped (هارب) | 🔴 أحمر |
| Bathroom (عذر حمام) | 🟡 أصفر |
| Late / Outside (متأخر وبرا) | 🟠 برتقالي |
| Absent (غائب) | ⚪ رمادي *(مقترح)* |
| Needs review (مراجعة) | 🔵 أزرق بإطار *(مقترح)* |

- **الحالات والألوان والأسماء متعرّفة في ملف إعدادات واحد**، فإضافة حالة أو تغيير لون سهل لمدارس تانية.
- **مكونات الصفحة:**
  - **رأس الصفحة:** الفصل (9 · Advanced · 4)، والحصة والمادة والوقت، وحالة الكاميرا ("Captured 09:43 by board").
  - **عدّادات** لكل حالة.
  - **فلاتر وبحث.**
  - **Bottom sheet:** لتغيير حالة الطالب + ملاحظة.
  - **شرح الألوان.**
  - **حالة "مفيش حصة دلوقتي"**، ومعاها الحصة الجاية.

**المرحلة دي (اللي هتتنفذ دلوقتي):**
- **شكل الصفحة بس:** الدخول وDashboard الحصة.
- **من غير** إيميلات ولا دخول حقيقي ولا اتصال بالسيرفر.
- تغيير الحالة بيظهر على الشاشة بس (local state) علشان تشوف الشكل والتفاعل، ومش بيتحفظ.
- **بيانات العرض:** أسماء **"Student 01 … Student 25"** في ملف منفصل `demo/` واضح إنه للعرض بس، علشان مفيش بيانات وهمية تدخل النظام الحقيقي.

## 6. الشبكة (محتاج قرار مع الـ IT)
- **الوضع الحالي:** كل جهاز على شبكة مختلفة. علشان كده الشاشات والمعلم والأدمن **مش هيوصلوا للسيرفر إلا لو له طريق من النت**، أو لو الـ IT ربط الشبكات ببعض.
- **"مش Public" ينفع يتحقق كده:**
  - **Cloudflare Tunnel + Cloudflare Access.** السيرفر هو اللي بيخرج للنت، ومفيش ولا منفذ مفتوح.
  - **أي حد مش مسجّل ما يقدرش يشوف حتى صفحة الدخول:**
    - الشاشات بمفتاح سري لكل شاشة.
    - المعلم والأدمن بكود بيوصل على الإيميل، أو جهاز متسجل.
  - ده محتاج دومين (حوالي 10$ في السنة)، أو اسم فرعي من دومين المدرسة.
- **البديل:** الـ IT يسمح لشبكة الشاشات وشبكة المعلمين يوصلوا لـ IP السيرفر على منفذ 443 بس. وكده كل حاجة تبقى داخلية.
- **في الحالتين:**
  - شبكة الطلاب والضيوف **ممنوع توصل** للسيرفر.
  - الشاشات ما بتبعتش غير نص.

```
├── server/          # FastAPI + SQLite: يستقبل نتايج الشاشات (نص بس) ولوحة أدمن صغيرة
├── studio/          # Python (PySide6): التصوير + التدريب + الجدول + التصدير للفلاشة → SSAS-Studio-Setup.exe
├── board-app/       # Android Kotlin: core (منطق بيتختبر على JVM) + app (الخدمة والكاميرا) → ssas-board.apk
└── .github/workflows/build.yml   # بيبني الـ .exe والـ APK ويعمل Release
```
صيغ الملفات اللي بتتنقل بين الأجهزة موثّقة في [`data-format.md`](data-format.md).
**مبادئ المرونة:**
- كل الحاجات الخاصة بالمدرسة (الحالات، والألوان، والتسميات، وأوقات النافذة، والحدود) **في ملفات إعدادات**، مش مكتوبة جوه الكود.
- النماذج قابلة للتبديل من الـ `manifest`.
- صيغة الـ JSON بين الشاشة والسيرفر **موثّقة ولها رقم نسخة**.
